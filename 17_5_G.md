# 17.5 — Infrastructure and tests (G1–G5)

Sub-plan of `17_REFACTOR.md` section G. G6 (dead code) landed in the
warm-ups; this covers the five that remain. Same cadence as before:
one commit per step, `cargo test` and clippy; for this section the
user has approved committing without per-step sign-off unless a
question comes up.
Gates per step: the pure refactors (G1, G4) run behind the 40-seed
simulate oracle (byte-identical CSV against a worktree build of the
previous commit); the save-format-adjacent ones (G1, G5) also run
behind `tests/save_compat.rs` and its corpus in `tests/saves`; the
test-only ones (G2, G3) behind `cargo test` alone.

## 1. Steps

### Step 1 — G5: the loader repairs with the seed it has

- `markets` gets `#[serde(default)]` (empty), and `save::sanitize`
  realizes the archetypes from the seed when the vector is empty —
  the same call `GameState::new` makes. Pre-M2 saves (`m1.json` in the
  corpus) get seed-perturbed markets instead of templates; the corpus
  test's "markets are present" assertion still holds and gains
  "and they match a fresh game on the same seed".
- `GameSeed` serializes through a one-field repr:
  `#[serde(from = "SeedRepr", into = "SeedRepr")]` with
  `struct SeedRepr { seed: u64 }`, so the wire shape `{"seed": N}` is
  unchanged and `From<SeedRepr>` calls `GameSeed::new`, which derives
  the contingent RNG. `fix_after_load` and `default_contingent_rng`
  go.
- Gate: `save_compat` corpus, full tests, oracle (new games are
  untouched, so byte-identical).

**Step 1 record.** `game_state::realize_world_markets(seed, balance,
start)` is the one realization; `GameState::new` calls it and
`save::sanitize` calls it for an empty `markets` (now a plain
`#[serde(default)]`), with the growth clock at `GameDate::default_start`.
`default_markets` is gone. `GameSeed` carries `#[serde(from = "SeedRepr",
into = "SeedRepr")]` with `SeedRepr { seed }`, so the wire form is still
`{"seed": N}` and loading goes through `GameSeed::new`; `fix_after_load`,
`default_contingent_rng` and the loader's call are gone. Every corpus
save turned out to carry a `markets` key (the m1 doc line was
optimistic), so the new corpus test strips the field from m1 in a temp
copy, loads it, and asserts the markets equal a fresh game's on the same
seed; a seed unit test pins the wire form and that a loaded seed's
contingent stream matches a fresh one's. Oracle byte-identical (2904 CSV
rows, 42 summary lines), 635 tests, clippy clean.

### Step 4 — G2: fixtures with one home

- `tests/common/mod.rs`: `temp_save_path`, `advance_through`,
  `fresh_game`; the integration suites `mod common;` it. The two
  `advance_through` copies are compared first; if they differ, the
  difference is the record.
- `src/test_util.rs` (`#[cfg(test)] pub mod test_util` in `lib.rs`):
  `bal()`, `test_rng()`, `kerolox_engine(...)`, the `stack` builder

- `GameState::for_test(seed)` (name fixed, money from the balance
  default) replaces the 119 `GameState::new(name, money, seed)` calls
  where the money is not the point of the test; `new` keeps its money
  parameter only if a test needs it (`save.rs` uses `100.0` to force a
  ledger shape; `tabs.rs` uses `100_000_000.0` for a poverty render).
  See Q1 for the $200M → $250M question.
- Gate: full tests; no runtime code changes, so no oracle run.

### Step 5 — G1: one allocator

- `src/id.rs`: `IdAllocator<T> { next: u64, _t: PhantomData<T> }` with
  `#[serde(transparent)]` (serde permits one non-skipped field) so
  every counter keeps its field name and its bare-integer wire form;
  `next(&mut self) -> T` via a `FromRaw` trait implemented by a
  `raw_ids!` macro for the 15 allocated id types; `Default` is zero,
  and the four `GameState` counters that default to 1 keep their
  `default = "..."` fns returning `IdAllocator::starting_at(1)`.
- The 14 counters change type; `apply_daily_work`, `generate_flaws`,
  `generate_third_party_flaws`, the contract and campaign generators
  take `&mut IdAllocator<FlawId>` / `<ContractId>` / `<CampaignId>`;
  the raw `+= 1` sites in `competitor.rs` and `game_state/mod.rs`
  become `.next()`. `Manufacturing`'s two wrapper methods become the
  allocator's own.
- The two oddities are decided in Q2 and Q3 before the step runs.
- Gate: oracle byte-identical (same sequences), `save_compat` corpus
  (same wire form), full tests.

Order: G5 and G4 first because they are small and each has one gate;
G3 before G2 so the fixture consolidation sees the final set of test
files; G1 last because it touches the tests G2 will have tidied and is
the only step with a save-format surface.

## 2. Questions for you

1. **G2, starting money.** Thirty-seven tests build a game with
   `$200M` while the balance default has been `$250M` since D-series.
   `GameState::for_test(seed)` could take the balance default, so
   there is one starting-money figure in the codebase and the tests
   see what a player sees; any test that then fails is a test that
   was quietly depending on the old number and gets looked at. Or it
   could take a named `TEST_STARTING_MONEY = 200M`, which keeps every
   test's behaviour but keeps a second figure. I'd try the default and
   report what breaks — expected to be few, since money only gates
   bankruptcy and affordability checks.
   USER:  Yeah, I expect moving to $250 won't hurt anything but we can revisit
   if it does.
   CLAUDE: Balance default it is; the step record will list any test
   that needed attention.

2. **G1, spacecraft ids.** `SpacecraftId` is minted from the rocket
   id counter at three sites, so a spacecraft never collides with a
   rocket and the two share one sequence. With allocators that is
   either `IdAllocator<RocketId>` plus `SpacecraftId::from(RocketId)`
   at those sites (keeps today's numbering and the save format), or a
   separate `next_spacecraft_id` counter (its own sequence; old saves
   would default it, and the loader would have to seed it past every
   existing spacecraft). I'd keep the shared sequence and make the
   conversion explicit.
   USER:  There aren't too many existing saves and they aren't really that big.
We want to be correct but seeding past all existing spacecraft isn't too big a
thing.
   CLAUDE: Separate `next_spacecraft_id` then, with `save::sanitize`
   seeding it past the highest spacecraft id in the save when the
   field is absent (serde default 0 → repaired to max+1). The three
   minting sites use it; rockets keep their own sequence. The corpus
   test gains an assertion that a loaded save's next spacecraft id is
   above every spacecraft it holds.

3. **G1, the bot's design id.** `BasicPolicy::build_template` sets
   the design's id to the *upcoming* rocket project id without

   allocator should not have a `peek`. The clean fix is for
   `start_rocket_project` to assign the design id from the project id
   it allocates (the designer path would then do the same), and the
   bot passes a design with a placeholder id. That is a small
   behaviour-neutral change to `Company` rather than the policy; is
   that acceptable inside G1, or should it be its own commit first?
   USER:  Lets break that out as a new commit
   CLAUDE: Step 5a, before the allocator: `start_rocket_project`
   assigns the design id from the project id it allocates, the bot
   and the designer stop pre-computing it. Oracle-gated (the ids come
   out the same).
