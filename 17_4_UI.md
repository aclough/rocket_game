# 17.4 — UI patterns (F1–F6)

Sub-plan of `17_REFACTOR.md` section F. F5 (labels) and F7 (terminal
guard) landed in the warm-ups; this covers the five that remain. Same
cadence: one commit per step, approval before each, `cargo test` and
clippy. The simulate oracle does not reach the UI, so the gate here is
the UI's own render tests (the pane-hint fit test, the help and
onboarding tests, the contract-table and designer render tests), plus
one addition in step 0: a smoke test that renders every tab and every
modal a fresh game can reach at 80 and 120 columns, so a moved helper
that panics or truncates is caught before anyone plays it.

## 1. Steps

### Step 0 — a render smoke test

`ui/tests` (or a module in `ui/mod.rs`): build a fresh game plus one
with an engine, a rocket, a flight and a parked spacecraft; render
every `Tab` and every reachable `InputMode` at 80×30 and 120×40 through
the same `render` helper the help tests use; assert no panic and no
line wider than the frame. Cheap, and it is what makes steps 1–5 safe
to do mechanically.

### Step 1 — F4: logic out of draw

- `Rocket::current_mass_kg(design, payload_kg)` (attached mass + payload)
  and `Rocket::current_accel_m_s2(design, payload_kg, sun_au)` (the
  active group's power-derated thrust over that mass);
  `RocketDesign::initial_accel_m_s2(payload_kg, sun_au)` for the pad.
- `Stage::power_summary(sun_au) -> (supply_w, housekeeping_w)` if the
  two panes really want the same pair; otherwise the existing
  `Stage::source_supply_w` / `housekeeping_w` suffice and the panes just
  call them.
- `ready_rockets_in_display_order` moves to `company/floor.rs` as
  `Company::ready_rockets_in_display_order`, next to the queue it
  mirrors; the launches tab and the launch key both call it there.
- Gate: render smoke test, existing tab tests; numbers on screen
  unchanged (the tests that read them say so).

### Step 2 — F2: one way to draw a list modal

- `draw/widgets.rs` gains `selected_style(bool)` (the `SELECTION_BG`
  background the contracts table already uses, bold), `selectable_line
  (text, selected)`, `modal_block(title)` and `render_list_modal(frame,
  area, title, lines, hint)`; `draw_modal`'s arms and the designer and
  editor modals use them.
- The border colour question (Cyan vs Yellow, unexplained) gets one
  answer — see Q1.
- Gate: render smoke test; the contract-table selection test already
  pins the background-not-foreground rule.

### Step 3 — F3: one text field

- `ui/text_field.rs`: `enum FieldEdit { Continue, Commit, Cancel }` and
  `edit_text_field(key, buffer: &mut String, numeric: bool) -> FieldEdit`
  (Esc → Cancel, Enter → Commit, Backspace pops, Char pushes if it fits
  the field's kind). The nine arms become "call it, act on the verdict".
- The four editor sub-modes collapse to two: `EngineEditorField {
  project_id, field: EditorField, buffer, state }` and the reactor
  twin, with `enum EditorField { Name, Scale }`; the `×√2` scale step
  lives once, in `editors.rs`.
- Gate: render smoke test plus the existing editor and bid-rule tests;
  a unit test on `edit_text_field` for the numeric filter.

### Step 4 — F1: cursors

- `ui/cursor.rs`: `Cursor { index }` with `up()`, `down(len)`,
  `clamp(len)`; the FlySelect/Dock/Undock/picker arms stop re-matching
  `&mut self.input_mode` to bump an index.
- `App::list_len_for(tab)` is the one place that knows how long each
  tab's list is; `handle_up`/`handle_down` and the draw side call it,
  so the six inline bounds go.
- Gate: render smoke test; the key-driven tests in `tabs.rs`.

### Step 5 — F6: the designer state stays put

- `InputMode::RocketDesigner { state, sub: DesignerSubMode }` where
  `DesignerSubMode` is `Main | PickEngine { target, inner, editing,
  booster, selected } | PayloadInput { buffer } | LocationPicker {
  selected } | PowerEditor { … } | Help`; the engine/reactor editors
  opened from the designer keep their `Option<Box<…>>` return slot,
  which is a different thing (an editor that may return to the
  designer).
- The eleven `RocketPickEngine { state, … }` reconstructions become
  `sub = …`; the `too_many_arguments` allow on
  `handle_rocket_pick_engine_key` goes.
- Medium risk: every designer key path changes shape. Last, once the
  smoke test covers the designer's modals.
